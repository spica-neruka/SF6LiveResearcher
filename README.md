# SF6 LIVE フロントエンド

スト6の配信中・配信予定・配信者を探す静的フロントエンドです。

## 起動とAPI

このフォルダーをHTTPサーバーで配信して `index.html` を開きます。ビルドは不要です。
APIの既定URLは `js/app.js` 内にあります。ローカル検証では、アプリの読み込み前に
`window.SF6_API_BASE` を設定することで検証用APIへ接続できます。

本番APIは許可されたサイトのOriginのみ受け付けます。ローカルで本番APIを使うために
本番のアクセス制限を変更する必要はありません。下記のブラウザ検証はAPIをモックします。

## 対応するバックエンド

隣接リポジトリ `../sf6-live-researcher` の変更と合わせて反映します。

- 配信・配信者一覧は `limit=200` で取得します。配信者カードは取得済みのデータから24件ずつ表示し、表示分が尽きた場合だけ次の200件を取得します。
- キーワード検索は取得済みのデータをブラウザ内で絞り込みます。入力・削除・検索だけの条件解除ではAPIを呼ばず、`q` パラメーターも送りません。未表示でも取得済みの配信者は検索対象です。
- 配信者のLIVE・予定表示は共通の配信一覧を再利用します。配信者ページでの `/api/favorites` 呼び出しは行いません。共通一覧が未取得の場合だけ取得し、未取得の続きがある場合は不明な配信者をオフラインと断定しません。
- 配信者のカテゴリ・活動形態は従来どおりAPIの絞り込み条件として送信します。
- 一覧の `hasNextPage` / `nextCursor`：総件数に依存しない追加読み込み。
- `GET /api/favorites?ids=...`：お気に入りページ専用。1回最大50チャンネル。配信中・予定・オフラインの情報を返します。

反映時はバックエンドを先に更新し、その後フロントエンドを公開してください。
今回のAPI追加にDBマイグレーションは不要です。既存バックエンドの前提となる
マイグレーションについては、バックエンド側READMEに従ってください。

## ブラウザ検証

Node.jsとPlaywrightが必要です。通常は次を実行します。

```sh
node scripts/verify-frontend.mjs
```

Playwrightを別の場所から利用する場合は `UI_PLAYWRIGHT_PATH` に `playwright/index.mjs` の
絶対パスを指定します。必要に応じて `UI_CHROMIUM_PATH` にChrome/Chromiumの実行ファイル、
`UI_OUTPUT_DIR` にスクリーンショットの保存先を指定できます。

検証は本番API・YouTubeへ接続せず、ローカルのソースと固定のAPI応答で行います。

## ザッピング（標準プレイヤー＋カルーセル）

配信中一覧の「ザッピングを開始」、またはカードの「ザッピングで見る」から開始します。検索・キャラクター・カテゴリ・並び順を適用した取得済みLIVEキューを再利用し、カード指定時はその配信から始めます。

- PCは中央に16:9のPlayer、左右に小さく見切れた前後サムネイルを表示します。スマホは中央の上下に前後サムネイルの一部を表示します。サムネイルのクリック・タップで1つ前／次へ切り替えます。先頭・末尾は無効表示となり、ループや追加取得はしません。
- Player外では ← / ↑ が前、→ / ↓ が次です。サムネイルとその周辺のホイール・上下スワイプにも対応します。ホイールは小delta累積・連続入力中1回・650msのクールダウンを維持し、キーrepeat・短い/横方向/複数指のスワイプは無視します。スワイプ後の合成クリックによる二重切替を防ぎます。
- YouTube標準の再生・一時停止・シーク・音量・設定・全画面・キーボード操作を使用します。`controls=1 / disablekb=0 / fs=1` とし、独自の再生・ミュートUIと映像上のジェスチャーレイヤーはありません。iframeに触れた入力はYouTube側で処理され、親ページが奪いません。配信情報部分は通常のページスクロールに使えます。
- `#persistent-player` は `#app` の外に1個だけ保持します。`#zapping-player-slot` の位置・幅・高さに合わせて大型表示し、サイト内移動で右下のミニ表示へ切り替えます。iframeをDOM上で移動・再生成せず、動画変更は `loadVideoById` のみです。最初はミュート、以後は同じPlayerの音量状態を保持します。
- 切替時はサムネイルをPCで横、スマホで縦に短くスライド・フェードさせます。中央Playerは固定し、`prefers-reduced-motion` ではアニメーションを無効にします。
- 大型の「閉じる」は画面ヘッダーに置きます。ミニの「大型に戻る」「閉じる」は映像の外の小さなヘッダーです。ミニでもYouTube標準controlsが使えます。メッセージも映像外に表示し、標準UIを覆いません。ページ再読み込み・別タブをまたぐ再生継続は対象外です。
- 配信者名・タイトル・カテゴリ・キャラクター・視聴者数・お気に入り・配信者情報画面への導線は中央Player下に表示します。配信者情報は取得済みデータを使います。

### APIとURL

開始・切替・大型／ミニ往復では `/api/videos`、D1、YouTube Data APIへの追加アクセスはありません。YouTube映像は [IFrame Player API](https://developers.google.com/youtube/iframe_api_reference) で直接再生します。URL直開き・リロード時だけ通常の初回LIVE取得が必要です。他画面の通常の初回取得・明示的な更新は従来どおりです。

`?view=zapping&video=VIDEO_ID` と `zap_character` / `zap_category` / `zap_sort` / `zap_q` で選択・フィルターを保存します。動画切替では履歴を増やさず、画面間移動は戻る/進むに対応します。現在の取得済み一覧にないIDは案内付きで先頭へ戻します。

キューと配信情報は開始時のスナップショットです。最新の一覧は通常の配信中ページで更新し、ザッピングを開始し直してください。終了・再生エラーの検知目的でAPIをポーリングしません。

### 検証

```sh
node scripts/verify-zapping.mjs
```

`UI_PLAYWRIGHT_PATH` / `UI_CHROMIUM_PATH` / `UI_OUTPUT_DIR` は既存検証と共通です。ローカルAPIとYouTube iframeをモックし、配信順・API回数・iframe同一性・標準操作への入力・カルーセル操作・URL・レスポンシブ配置をブラウザで検証します。実際のYouTube映像配信や広告・端末固有の全画面表示はこのモック検証の対象外です。
