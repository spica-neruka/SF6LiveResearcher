# SF6 LIVE フロントエンド

スト6の配信中・配信予定・配信者を探す静的フロントエンドです。

## 起動とAPI

このフォルダーをHTTPサーバーで配信して `index.html` を開きます。ビルドは不要です。
APIの既定URLは `js/app.js` 内にあります。ローカル検証では、アプリの読み込み前に
`window.SF6_API_BASE` を設定することで検証用APIへ接続できます。

本番APIは許可されたサイトのOriginのみ受け付けます。ローカルで本番APIを使うために
本番のアクセス制限を変更する必要はありません。下記のブラウザ検証はAPIをモックします。

## 対応するバックエンド

隣接リポジトリ `../sf6-live-researcher` の変更と合わせて反映します。

- 配信・配信者一覧は `limit=200` で取得します。配信者カードは取得済みのデータから24件ずつ表示し、表示分が尽きた場合だけ次の200件を取得します。
- キーワード検索は取得済みのデータをブラウザ内で絞り込みます。入力・削除・検索だけの条件解除ではAPIを呼ばず、`q` パラメーターも送りません。未表示でも取得済みの配信者は検索対象です。
- 配信者のLIVE・予定表示は共通の配信一覧を再利用します。配信者ページでの `/api/favorites` 呼び出しは行いません。共通一覧が未取得の場合だけ取得し、未取得の続きがある場合は不明な配信者をオフラインと断定しません。
- 配信者のカテゴリ・活動形態は従来どおりAPIの絞り込み条件として送信します。
- 一覧の `hasNextPage` / `nextCursor`：総件数に依存しない追加読み込み。
- `GET /api/favorites?ids=...`：お気に入りページ専用。1回最大50チャンネル。配信中・予定・オフラインの情報を返します。

反映時はバックエンドを先に更新し、その後フロントエンドを公開してください。
今回のAPI追加にDBマイグレーションは不要です。既存バックエンドの前提となる
マイグレーションについては、バックエンド側READMEに従ってください。

## ブラウザ検証

Node.jsとPlaywrightが必要です。通常は次を実行します。

```sh
node scripts/verify-frontend.mjs
```

Playwrightを別の場所から利用する場合は `UI_PLAYWRIGHT_PATH` に `playwright/index.mjs` の
絶対パスを指定します。必要に応じて `UI_CHROMIUM_PATH` にChrome/Chromiumの実行ファイル、
`UI_OUTPUT_DIR` にスクリーンショットの保存先を指定できます。

検証は本番API・YouTubeへ接続せず、ローカルのソースと固定のAPI応答で行います。

## ザッピングV1

- 配信中の「ザッピングを開始」またはカードの「ザッピングで見る」で開始します。検索・キャラクター・配信カテゴリ・並び順を適用した取得済みLIVE一覧をキューに保存し、カード指定時はその動画から開始します。
- 開始・前後の切替・ミニ表示・大型への復帰では `/api/videos`、D1、YouTube Data APIを呼びません。URLの直開き・リロード時のみ、通常の初回LIVE一覧取得が必要です。未取得の続きは自動取得せず、最後で停止します。
- PCは映像下の操作エリアでホイール上下、↑ / ↓キー、前へ / 次へボタンを使用できます。スマホは操作エリア・配信情報部分を上下スワイプします。YouTube iframe内の入力は親ページに伝わらないため、映像内ではYouTube標準操作が優先されます。
- ホイールは小さいdeltaを累積し、同じ連続入力中は1回のみ切り替え、650msのクールダウンも適用します。キーのリピート・短いスワイプ・横スワイプ・複数指は切替対象外です。
- `js/zapping-player.js` は [YouTube IFrame Player API](https://developers.google.com/youtube/iframe_api_reference) を開始時に遅延ロードします。`#app` の外に1個のプレイヤーを維持し、DOMの移動・再生成なしで大型と右下ミニ表示を切り替えます。動画変更は `loadVideoById` です。最初はミュート、以後は同じプレイヤーの音量設定を保持します。
- 自動再生ブロック・埋め込み不可・配信終了時は案内を表示します。「再生」「YouTubeで開く」「次へ」で対応でき、終了検知のためのAPIポーリングはありません。大型は16:9、狭いスマホとミニ表示はYouTubeの最小高さ200pxを確保します。
- サイト内移動ではミニプレイヤーに再生/停止・ミュート・閉じる・大型への復帰を表示します。「配信者を見る」は取得済みデータによるサイト内の配信者情報画面です。ページ再読み込み・別タブをまたぐ再生継続は対象外です。
- `?view=zapping&video=VIDEO_ID` に選択状態を反映し、絞り込みは `zap_character` / `zap_category` / `zap_sort` / `zap_q` に保存します。動画切替は履歴を増やさず、ページ間移動は戻る/進むに対応します。未知・終了済みなど現在の取得済み一覧にないIDは案内付きで先頭へ戻ります。
- キューと配信情報は開始時のスナップショットです。最新情報は配信中一覧の通常更新後に、一覧からザッピングを開始し直して取り込みます。他画面の通常の初回取得・明示的な更新は従来どおりです。

追加のブラウザ検証（APIとYouTubeプレイヤーをモック）:

```sh
node scripts/verify-zapping.mjs
```

`UI_PLAYWRIGHT_PATH` / `UI_CHROMIUM_PATH` / `UI_OUTPUT_DIR` は既存検証と共通です。
